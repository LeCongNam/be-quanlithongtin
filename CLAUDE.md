# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Backend for a university library management system (đồ án môn Quản lý thông tin, DB name `qltv_nhom8`). NestJS 12 + Prisma 6 + MySQL 8. Domain naming is Vietnamese (`docgia` = reader, `nguoi_dung` = user, `sach` = book, `phieu_muon` = loan slip, `phieu_phat` = fine, `dat_truoc` = reservation). The README is the stock NestJS template except for the Prisma/MySQL section.

## Commands

```bash
npm install
cp .env.example .env                  # DATABASE_URL (user qltt, khớp docker-compose) + JWT_SECRET (bắt buộc)
docker compose up -d db               # MySQL 8.0, port 3306, auto-runs ./sql/99_full_setup.sql on first start only
                                      # nạp lại schema: docker compose down -v && docker compose up -d db
npm run prisma:pull                   # introspect DB -> prisma/schema.prisma (xem gotchas bên dưới)
npm run prisma:generate               # regenerate Prisma Client (required after schema changes)

npm run start:dev                     # watch mode (PORT env, default 3000)
npm run build                         # nest build (deleteOutDir) ; npm run start:prod runs dist/main
npm run lint                          # oxlint --type-aware (not eslint)
npm run format                        # prettier (single quotes, trailing commas)

npm test                              # vitest unit tests (**/*.spec.ts)
npm run test:e2e                      # vitest e2e (**/*.e2e-spec.ts, test/) - cần DB docker đang chạy, dùng tài khoản seed ad001/AD001@Nhom8
npx vitest run src/app.controller.spec.ts        # single file
npx vitest run -t "test name"                    # single test by name
```

Both `package-lock.json` and `yarn.lock` exist; `package.json` scripts and README use npm.

## Architecture

- **Database-first.** The schema lives in SQL, not in Prisma migrations. `prisma/schema.prisma` is generated by `prisma db pull` and uses `@map` to translate snake_case tables/columns into camelCase models (e.g. `NguoiDung` -> `nguoi_dung`, `maNguoiDung` -> `ma_nguoi_dung`). Do not hand-design migrations; change the SQL, then re-pull and re-generate.
- **One SQL source.** `sql/00..09_*.sql` is the canonical schema, copied from `../database_info/database/` (14 tables, 17 procedures, 12 triggers, 7 functions, 2 events, 6 views). `sql/99_full_setup.sql` is the concatenation of 00..08 (drops and recreates the DB — destructive) and is what docker-compose mounts. `08b_create_users.sql` and `09_smoke_test.sql` are not part of it. When `database_info` changes, re-copy the files here. There is no `init.sql` any more.
- **Business logic stays in MySQL.** Loan/return/renew/reserve/fine rules are procedures + triggers; the BE only calls `CALL sp_*` (via `$queryRaw`/`$executeRaw`) and reads views. Do not re-implement these rules in services. Procedures take _codes_ (`ma_nguoi_dung`, `ma_ban_sach`, `ma_sach`, `ma_phieu`), not ids.
- **App wiring.** `src/main.ts` creates the app with `ObserveInstrument` (`@nestjs/observe`, created in `src/app.module.ts` via `createObserveModule()`; `ObserveModule` is not yet in `imports`), a global `ValidationPipe({ transform: true, whitelist: true })`, Swagger at `/docs`, and imports `common/bigint-json.ts` (BigInt -> string in JSON). `ConfigModule` and `PrismaModule` are global. `AuthModule` registers global guards: `JwtAuthGuard` (everything needs a Bearer token unless `@Public()`) then `RolesGuard` (`@Roles(...)` on class or handler; handler wins). `DatabaseExceptionFilter` (APP_FILTER) maps DB errors: `SIGNAL 45000` -> 422 with the Vietnamese message, P2002/P2003 -> 409, P2025 -> 404, CHECK violation -> 400.
- **Feature modules** (`module / controller / service / dto/`): `auth` (POST /auth/login, GET /auth/me), `docgia` (CRUD on `nguoi_dung`, DELETE = set NGUNG + lock account, POST :id/tai-khoan creates a login), `danh-muc` (the-loai, nha-xuat-ban, tac-gia), `sach` (+ ban-sach, search via `sp_tra_cuu_sach`), `muon-tra` (phieu-muon, tra, gia-han), `dat-truoc`, `phat`, `ban-doc` (`/me/*`), `bao-cao` (views). Staff = ADMIN/THU_THU; reads of catalogs are open to any logged-in user.
- **Auth.** JWT payload is `AuthUser` (`nguoiDungId`, `maNguoiDung`, `tenDangNhap`, `vaiTro`). Passwords are bcrypt (`bcryptjs`); seed accounts use legacy `SHA2(muoi + password)` and are re-hashed to bcrypt on first successful login. Readers share one MySQL user, so the BE must force the caller's `maNguoiDung` from the token (`resolveMaNguoiDung` in `common/auth-helpers.ts`) — never trust it from the client for non-staff.
- **BigInt IDs.** All primary keys are `BIGINT`, so Prisma returns `BigInt`. `bigint-json.ts` serializes them as strings; route params use `ParseBigIntPipe`.

## Conventions / gotchas

- ESM project (`"type": "module"`, `module: nodenext`): **relative imports must include the `.js` extension** (`import { X } from './x.service.js'`) even though the files are `.ts`.
- Tests use Vitest with `globals: true` (not Jest); `emitDecoratorMetadata` is on, so keep decorator-based DI imports as value imports (not `import type`).
- `prisma db pull` caveats: (1) CHECK-constrained columns come back as `String`, so the enums live in `src/common/db-enums.ts` (TS), not in the Prisma schema; (2) renamed models/fields are preserved on re-pull, but _new_ columns arrive snake_case — rename to camelCase + `@map` by hand (e.g. `giaBia`, `ThamSo`); (3) GENERATED columns (`banSachDangMuon`, `khoaDangHoatDong`, `banSachDangGiu`) are read-only, never write them; (4) the pulled default for `Sach.ngonNgu` can show up as mojibake if the DB was loaded with the wrong charset — it must read `"Tiếng Việt"`.
- Docker MySQL is started with `--character-set-client-handshake=FALSE`; without it the entrypoint loads the SQL as latin1 and Vietnamese text is double-encoded in the DB.
- ``prisma.$queryRaw`CALL sp_...` `` returns columns as `f0, f1, ...` (names lost). Use `namedRows` + the column lists in `src/common/call-rows.ts`, and keep them in sync with `sql/04_procedures.sql`. Procedures with `OUT` params need an interactive `$transaction` (same connection) plus `SELECT @var`.
- `.oxlintrc.json` enforces `typescript/no-floating-promises` as an error; `no-explicit-any` is off.

## Git safety — hard rules

- **NEVER run `git commit` or `git push` unless the user asks for it in the current message.**
- Do not stage changes or open PRs automatically after finishing a task.
- Leave modified files in the working directory for the user to review.

### Branch / worktree naming

Always branch (and create any worktree) off `main` when starting a
task. This is a team project, so the branch name is
`<author>/<type>/<feature>`:

- `<author>`: the developer's name, lowercase, no diacritics, no spaces. Use enough of the
  name to be unique in the team (there are two people called "Minh", so use the full
  given-name pair, not just "minh").
- `<type>`: the task-type prefix from the table below, without its trailing slash.
- `<feature>`: short kebab-case description of the work.

Example: Trọng Minh adding a feature -> `trongminh/feat/be-foundation-modules` Task types:

| Task type                    | Prefix      |
| ---------------------------- | ----------- |
| Bug fix                      | `fix/`      |
| Enhancement                  | `enhancer/` |
| New feature                  | `feat/`     |
| Improvement                  | `improve/`  |
| Hotfix (production incident) | `hotfix/`   |

### Commit messages

- Short and to the point, describing the actual task/fix/feature — no filler, no restating the diff.
- **Never** include `Co-Authored-By: Claude`, any other AI attribution, or any signature/trailer of
  any kind. Plain message only.
