# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Backend for a university library management system (đồ án môn Quản lý thông tin, DB name `qltv_nhom8`). NestJS 12 + `mysql2` (SQL thuần, không ORM) + MySQL 8. Domain naming is Vietnamese (`docgia` = reader, `nguoi_dung` = user, `sach` = book, `phieu_muon` = loan slip, `phieu_phat` = fine, `dat_truoc` = reservation). The README is the stock NestJS template except for the MySQL section.

## Architecture

- **Raw SQL, no ORM.** The schema lives in SQL (`sql/`), the BE reads/writes with hand-written queries through `DbService` (`src/database/`, a `mysql2/promise` pool). Services build camelCase JSON from snake_case rows (`camelize`/`camelizeAll`, `database/rows.ts`) and nest related rows by JOIN or a second `IN (...)` query (see `phat`, `dat-truoc`, `muon-tra`). Do not hand-design migrations; change the SQL files.
- **One SQL source.** `sql/00..10_*.sql` is the canonical schema, copied from `../database_info/database/` (15 tables, 30 procedures, 12 triggers, 9 functions, 3 events, 9 views). `sql/99_full_setup.sql` is the concatenation of 00..08 generated by `sql/build_full_setup.sh` (never edit by hand; drops and recreates the DB — destructive) and is what docker-compose mounts. `08b_create_users.sql`, `09_smoke_test.sql` and `10_regression_test.sql` are not part of it. When `database_info` changes, re-copy all files (incl. `build_full_setup.sh`), check `99` matches a rebuild, read `../database_info/docs/05_nhat_ky_sua_loi.md` for the new items, then reload docker and adjust the affected queries in `src/`. There is no `init.sql` any more.
- **Business logic stays in MySQL.** Loan/return/renew/reserve/fine rules, adding books/copies (`sp_them_sach`, `sp_them_ban_sach`) and reader status (`sp_doi_trang_thai_nguoi_dung`) are procedures + triggers; the BE only calls `CALL sp_*` (`db.call(name, args)`) and reads views. Do not re-implement these rules in services. Procedures take _codes_ (`ma_nguoi_dung`, `ma_ban_sach`, `ma_sach`, `ma_phieu`), not ids.
- **Transactions.** Every writing procedure does its own `START TRANSACTION … COMMIT` when `@@autocommit = 1`. A plain `db.transaction` (START TRANSACTION) is for DML only: procedures run their own `START TRANSACTION`, which implicitly COMMITs earlier work. To group several `CALL`s use `db.procTransaction` (`SET autocommit = 0` … `COMMIT`/`ROLLBACK` on one connection, autocommit restored afterwards); `db.session` gives one connection for `@var`/OUT params (`CALL sp_x(?, @out)` then `SELECT @out`). A single `CALL` needs no wrapper.
- **DB reader sessions are not used.** The DB has token sessions for readers (`phien_dang_nhap`, `sp_dang_nhap`, `sp_bandoc_*(token, …)`) meant for apps that connect as the shared `qltv_bandoc` MySQL user. This BE authenticates itself (JWT, connects as `qltt`), so it never calls `sp_dang_nhap`/`sp_bandoc_*`: `/me/*` reads the same views/columns as those procedures filtered by the JWT's `maNguoiDung`, and reader renewals call `sp_gia_han_luot_muon(ma_ban_sach, so_ngay, ma_nguoi_dung)` (owner check inside its `FOR UPDATE`). The password format is shared with `sp_dang_nhap` on purpose (two-layer auth demo: DB layer via DBeaver, app layer via this BE) — never write another hash format into `tai_khoan`.
- **App wiring.** `src/main.ts` creates the app with `ObserveInstrument` (`@nestjs/observe`, created in `src/app.module.ts` via `createObserveModule()`; `ObserveModule` is not yet in `imports`), a global `ValidationPipe({ transform: true, whitelist: true })`, Swagger via `setupSwagger` (`src/openapi.ts`: `/docs`, `/docs-json`, `/docs-yaml`), CORS from `CORS_ORIGINS`, and imports `common/bigint-json.ts` (BigInt -> string in JSON). `ConfigModule` and `DatabaseModule` (`DbService`) are global. `AuthModule` registers global guards: `JwtAuthGuard` (everything needs a Bearer token unless `@Public()`; after verifying the JWT it reads `tai_khoan`/`nguoi_dung` status from the DB on every request, so a locked account loses access immediately, not when the JWT expires) then `RolesGuard` (`@Roles(...)` on class or handler; handler wins). `DbService` wraps driver errors as `DatabaseError` (errno/sqlMessage) and `executeOne` throws `RecordNotFoundError` when an UPDATE/DELETE by key matches no row; `DatabaseExceptionFilter` (APP_FILTER, `database/db-error.ts`) maps them: errno 1644 (`SIGNAL 45000`) -> 422 with the Vietnamese message, 1062 -> 409, 1217/1451/1452 (FK) -> 409, 3819 (CHECK) -> 400, `RecordNotFoundError` -> 404, anything else -> 500.
- **Feature modules** (`module / controller / service / dto/`): `auth` (POST /auth/login, GET /auth/me), `docgia` (CRUD on `nguoi_dung`; new users are always HOAT_DONG; `PATCH :id/trang-thai` via `sp_doi_trang_thai_nguoi_dung` for readers, CAN_BO only by ADMIN directly; DELETE = same flow to NGUNG; trigger locks the account but never reopens it -> ADMIN `PATCH :id/tai-khoan/trang-thai`; POST :id/tai-khoan creates a login), `danh-muc` (the-loai, nha-xuat-ban, tac-gia; create/update by staff, DELETE only ADMIN to match `r_qltv_thuthu` grants), `sach` (create via `sp_them_sach` with `maTheLoai/maNxb/maTacGias`; `POST sach/:id/ban-sach {soBan, viTriKe}` via `sp_them_ban_sach`, codes `BSnnn` generated; search via `sp_tra_cuu_sach`), `muon-tra` (phieu-muon, tra, gia-han), `dat-truoc`, `phat`, `ban-doc` (`/me/sach-dang-muon|tien-phat|lich-su-muon|dat-truoc`), `bao-cao` (8 views; `vw_tra_cuu_sach` is used by GET /sach), `demo` (staff only; the exam's Procedure/Trigger/Function/Cursor demo: `demo.catalog.ts` holds problem text, params, the statement to run and the related-table queries, `demo.service.ts` runs them. `POST /demo/:id/chay` runs inside `autocommit = 0` and ROLLBACKs by default (`hoanTac`), reading the tables after the call but before the rollback; business errors come back in `loi`, not as 422. Routine/trigger SQL text: `SHOW CREATE` returns NULL for `qltt`, so it is read from `sql/03..06_*.sql` — keep catalog names in sync with those files). Staff = ADMIN/THU_THU; reads of catalogs are open to any logged-in user.
- **Auth.** JWT payload is `AuthUser` (`nguoiDungId`, `maNguoiDung`, `tenDangNhap`, `vaiTro`). Passwords have ONE format, `SHA2(muoi + password)` hex (`common/password.ts`), identical to `sp_dang_nhap`, so web-created/logged-in accounts still work at the DB layer. Legacy bcrypt hashes (`$2…`, from older BE versions) are still accepted and rewritten to SHA2 on first correct login (`bcryptjs` kept only for that). Readers share one MySQL user, so the BE must force the caller's `maNguoiDung` from the token (`resolveMaNguoiDung` in `common/auth-helpers.ts`) — never trust it from the client for non-staff.
- **BigInt IDs.** All primary keys are `BIGINT`. The pool runs with `supportBigNumbers` + `bigNumberStrings`, so ids and COUNTs arrive (and serialize) as strings; DECIMAL arrives as a string with trailing zeros trimmed (`85000.00` -> `"85000"`); DATE/DATETIME as `Date` read in UTC (`timezone: 'Z'`). Route params use `ParseBigIntPipe` and bind as `bigint`. Never concatenate client input into SQL: use `sql\`...${value}...\`` (binds `?`), `raw()` only for whitelisted column names, and `likeContains` + `ESCAPE_LIKE` for LIKE searches (`database/sql.ts`).

## Conventions / gotchas

- **Swagger/OpenAPI is part of the contract with FE** (`docs/swagger-cho-fe.md`). Every endpoint needs `@ApiOperation({ summary })`, a response schema (`@ApiOkResponse`/`@ApiCreatedResponse`/`ApiPaginatedResponse` with a class from `**/dto/*.response.dto.ts`) and the error codes it can return (`ApiErrors(...)` on the class). BIGINT ids use `ApiBigInt`, Decimal `ApiDecimal`, DB enums `ApiEnum(enum, 'Name')` (`common/swagger/api-types.ts`). The "Quyền" line and `x-roles` of each operation are generated from the real `@Roles`/`@Public` metadata in `openapi.ts`, so never write roles by hand in descriptions. `test/openapi.e2e-spec.ts` fails when an endpoint lacks summary/response schema/401/403. Use `PartialType` from `@nestjs/swagger` (not `@nestjs/mapped-types`) so Update DTOs keep their schema; fields with a default value (`page = 1`) need `@ApiPropertyOptional` or the spec marks them required.
- The Nest CLI Swagger plugin (`nest-cli.json`) infers request DTO schemas only in `nest build`/`nest start`, not in vitest, so `test/openapi.e2e-spec.ts` can only assert what is declared explicitly. To check a spec change end to end, run `npm run openapi:export` and compare real responses with it (responses of views/`CALL`s are plain rows: BIGINT/DECIMAL arrive as strings unless converted with `numberColumns` in `common/call-rows.ts`; keep every count/amount column a number).
- **Do not build or run from a directory whose path has decomposed Vietnamese diacritics (macOS NFD, e.g. `Quản` = `Qua` + U+0309)**: the Swagger plugin then emits a wrong relative `import` and `node dist/main` fails with `ERR_MODULE_NOT_FOUND`. Use an ASCII path (copy/clone the repo there).
- MySQL 8 reports FK violations as error 1217/1451/1452; all three map to 409.

- ESM project (`"type": "module"`, `module: nodenext`): **relative imports must include the `.js` extension** (`import { X } from './x.service.js'`) even though the files are `.ts`.
- Tests use Vitest with `globals: true` (not Jest); `emitDecoratorMetadata` is on, so keep decorator-based DI imports as value imports (not `import type`).
- GENERATED columns (`ban_sach_dang_muon` in `ct_phieu_muon`, `khoa_dang_hoat_dong`/`ban_sach_dang_giu` in `dat_truoc`) are read-only: never list them in INSERT/UPDATE (they still appear in `SELECT *`/responses). If the DB was loaded with the wrong charset, `sach.ngon_ngu`'s default shows mojibake — it must read `Tiếng Việt`; the pool uses `charset: 'utf8mb4'`.
- Docker MySQL is started with `--character-set-client-handshake=FALSE`; without it the entrypoint loads the SQL as latin1 and Vietnamese text is double-encoded in the DB.
- `CALL sp_...` through `db.call` returns the real column names of the procedure's first result set (no positional mapping). Procedures with `OUT` params need one connection: `db.session`/`db.procTransaction`, then `SELECT @var`. `mysql2` `query` (client-side `?` binding) is used instead of `execute`, because prepared statements break `LIMIT ? OFFSET ?` and `IN (?)` expansion.
- `sp_tra_cuu_sach` trims the keyword, treats `% _ \` literally, returns nothing for an empty keyword, and uses a FULLTEXT ngram index (Vietnamese short syllables like "cơ sở" match). Results are ordered by relevance tier (exact `ma_sach`/ISBN, exact title, title prefix, title contains, author match, description-only), then `ten_sach`, `ma_sach`; `sapXep` overrides this in `SachService`. All `SIGNAL`/function messages in `sql/03..06` are Vietnamese with diacritics; `sql/10_regression_test.sql` compares message text, so update both together. Paged lists are backed by `idx_pm_ngay_muon`, `idx_pp_trang_thai_ngay_tao`, `idx_dt_ngay_dat`. `sp_them_sach_vao_phieu` only accepts slips created today.
- `.oxlintrc.json` enforces `typescript/no-floating-promises` as an error; `no-explicit-any` is off.

## Git safety — hard rules

- **NEVER run `git commit` or `git push` unless the user asks for it in the current message.**
- Do not stage changes or open PRs automatically after finishing a task.
- Leave modified files in the working directory for the user to review.

### Branch / worktree naming

Always branch (and create any worktree) off `main` when starting a
task, This is a team project, so the branch name is
`<author>`:

Example: Trọng Minh adding a feature -> `trongminh`

### Commit messages

- Short and to the point, describing the actual task/fix/feature — no filler, no restating the diff.
- **Never** include `Co-Authored-By: Claude`, any other AI attribution, or any signature/trailer of
  any kind. Plain message only.
