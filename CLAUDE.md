## Project

Backend for a university library management system (đồ án môn Quản lý thông tin, DB name `qltv_nhom8`). NestJS 12 + Prisma 6 + MySQL 8. Domain naming is Vietnamese (`docgia` = reader, `nguoi_dung` = user, `sach` = book, `phieu_muon` = loan slip, `phieu_phat` = fine, `dat_truoc` = reservation). The README is the stock NestJS template except for the Prisma/MySQL section.

## Architecture

- **Database-first.** The schema lives in SQL, not in Prisma migrations. `prisma/schema.prisma` is generated by `prisma db pull` and uses `@map` to translate snake_case tables/columns into camelCase models (e.g. `NguoiDung` -> `nguoi_dung`, `maNguoiDung` -> `ma_nguoi_dung`). Do not hand-design migrations; change the SQL, then re-pull and re-generate.
- **One SQL source.** `sql/00..10_*.sql` is the canonical schema, copied from `../database_info/database/` (15 tables, 30 procedures, 12 triggers, 9 functions, 3 events, 9 views). `sql/99_full_setup.sql` is the concatenation of 00..08 generated by `sql/build_full_setup.sh` (never edit by hand; drops and recreates the DB — destructive) and is what docker-compose mounts. `08b_create_users.sql`, `09_smoke_test.sql` and `10_regression_test.sql` are not part of it. When `database_info` changes, re-copy all files (incl. `build_full_setup.sh`), check `99` matches a rebuild, read `../database_info/docs/05_nhat_ky_sua_loi.md` for the new items, then reload docker + re-pull Prisma. There is no `init.sql` any more.
- **Business logic stays in MySQL.** Loan/return/renew/reserve/fine rules, adding books/copies (`sp_them_sach`, `sp_them_ban_sach`) and reader status (`sp_doi_trang_thai_nguoi_dung`) are procedures + triggers; the BE only calls `CALL sp_*` (via `$queryRaw`/`$executeRaw`) and reads views. Do not re-implement these rules in services. Procedures take _codes_ (`ma_nguoi_dung`, `ma_ban_sach`, `ma_sach`, `ma_phieu`), not ids.
- **Transactions.** Every writing procedure does its own `START TRANSACTION … COMMIT` when `@@autocommit = 1`. A bare `prisma.$transaction` keeps autocommit = 1, so the first procedure implicitly COMMITs and a later failure cannot undo earlier calls. To group several `CALL`s use `withProcTransaction` (`src/common/proc-transaction.ts`: `SET autocommit = 0` … `COMMIT`/`ROLLBACK`, then restore autocommit). A single `CALL` needs no wrapper.
- **DB reader sessions are not used.** The DB has token sessions for readers (`phien_dang_nhap`, `sp_dang_nhap`, `sp_bandoc_*(token, …)`) meant for apps that connect as the shared `qltv_bandoc` MySQL user. This BE authenticates itself (JWT, connects as `qltt`), so it never calls `sp_dang_nhap`/`sp_bandoc_*`: `/me/*` reads the same views/columns as those procedures filtered by the JWT's `maNguoiDung`, and reader renewals call `sp_gia_han_luot_muon(ma_ban_sach, so_ngay, ma_nguoi_dung)` (owner check inside its `FOR UPDATE`). The password format is shared with `sp_dang_nhap` on purpose (two-layer auth demo: DB layer via DBeaver, app layer via this BE) — never write another hash format into `tai_khoan`.
- **App wiring.** `src/main.ts` creates the app with `ObserveInstrument` (`@nestjs/observe`, created in `src/app.module.ts` via `createObserveModule()`; `ObserveModule` is not yet in `imports`), a global `ValidationPipe({ transform: true, whitelist: true })`, Swagger at `/docs`, and imports `common/bigint-json.ts` (BigInt -> string in JSON). `ConfigModule` and `PrismaModule` are global. `AuthModule` registers global guards: `JwtAuthGuard` (everything needs a Bearer token unless `@Public()`; after verifying the JWT it reads `tai_khoan`/`nguoi_dung` status from the DB on every request, so a locked account loses access immediately, not when the JWT expires) then `RolesGuard` (`@Roles(...)` on class or handler; handler wins). `DatabaseExceptionFilter` (APP_FILTER) maps DB errors: `SIGNAL 45000` -> 422 with the Vietnamese message (from raw `CALL`s as P2010, and from triggers fired by Prisma model writes as an unknown-request error whose text contains `MysqlError { code: 1644, … }`), P2002/P2003 -> 409, P2025 -> 404, CHECK violation -> 400.
- **Feature modules** (`module / controller / service / dto/`): `auth` (POST /auth/login, GET /auth/me), `docgia` (CRUD on `nguoi_dung`; new users are always HOAT_DONG; `PATCH :id/trang-thai` via `sp_doi_trang_thai_nguoi_dung` for readers, CAN_BO only by ADMIN directly; DELETE = same flow to NGUNG; trigger locks the account but never reopens it -> ADMIN `PATCH :id/tai-khoan/trang-thai`; POST :id/tai-khoan creates a login), `danh-muc` (the-loai, nha-xuat-ban, tac-gia; create/update by staff, DELETE only ADMIN to match `r_qltv_thuthu` grants), `sach` (create via `sp_them_sach` with `maTheLoai/maNxb/maTacGias`; `POST sach/:id/ban-sach {soBan, viTriKe}` via `sp_them_ban_sach`, codes `BSnnn` generated; search via `sp_tra_cuu_sach`), `muon-tra` (phieu-muon, tra, gia-han), `dat-truoc`, `phat`, `ban-doc` (`/me/sach-dang-muon|tien-phat|lich-su-muon|dat-truoc`), `bao-cao` (8 views; `vw_tra_cuu_sach` is used by GET /sach). Staff = ADMIN/THU_THU; reads of catalogs are open to any logged-in user.
- **Auth.** JWT payload is `AuthUser` (`nguoiDungId`, `maNguoiDung`, `tenDangNhap`, `vaiTro`). Passwords have ONE format, `SHA2(muoi + password)` hex (`common/password.ts`), identical to `sp_dang_nhap`, so web-created/logged-in accounts still work at the DB layer. Legacy bcrypt hashes (`$2…`, from older BE versions) are still accepted and rewritten to SHA2 on first correct login (`bcryptjs` kept only for that). Readers share one MySQL user, so the BE must force the caller's `maNguoiDung` from the token (`resolveMaNguoiDung` in `common/auth-helpers.ts`) — never trust it from the client for non-staff.
- **BigInt IDs.** All primary keys are `BIGINT`, so Prisma returns `BigInt`. `bigint-json.ts` serializes them as strings; route params use `ParseBigIntPipe`.

## Conventions / gotchas

- ESM project (`"type": "module"`, `module: nodenext`): **relative imports must include the `.js` extension** (`import { X } from './x.service.js'`) even though the files are `.ts`.
- Tests use Vitest with `globals: true` (not Jest); `emitDecoratorMetadata` is on, so keep decorator-based DI imports as value imports (not `import type`).
- `prisma db pull` caveats: (1) CHECK-constrained columns come back as `String`, so the enums live in `src/common/db-enums.ts` (TS), not in the Prisma schema; (2) renamed models/fields are preserved on re-pull, but _new_ columns arrive snake_case — rename to camelCase + `@map` by hand (e.g. `giaBia`, `ThamSo`); (3) GENERATED columns (`banSachDangMuon`, `khoaDangHoatDong`, `banSachDangGiu`) are read-only, never write them; relation fields can also come back snake_case (e.g. `ban_sach`, `dat_truoc`) — rename them back (`banSach`, `datTruocs`, `phienDangNhaps`); (4) the pulled default for `Sach.ngonNgu` can show up as mojibake if the DB was loaded with the wrong charset — it must read `"Tiếng Việt"`.
- Docker MySQL is started with `--character-set-client-handshake=FALSE`; without it the entrypoint loads the SQL as latin1 and Vietnamese text is double-encoded in the DB.
- ``prisma.$queryRaw`CALL sp_...` `` returns columns as `f0, f1, ...` (names lost). Use `namedRows` + the column lists in `src/common/call-rows.ts`, and keep them in sync with `sql/04_procedures.sql`. Procedures with `OUT` params need an interactive `$transaction` (same connection) plus `SELECT @var`.
- `sp_tra_cuu_sach` trims the keyword, treats `% _ \` literally, returns nothing for an empty keyword, and uses a FULLTEXT ngram index (Vietnamese short syllables like "cơ sở" match). `sp_them_sach_vao_phieu` only accepts slips created today.
- `.oxlintrc.json` enforces `typescript/no-floating-promises` as an error; `no-explicit-any` is off.

## Git safety — hard rules

- **NEVER run `git commit` or `git push` unless the user asks for it in the current message.**
- Do not stage changes or open PRs automatically after finishing a task.
- Leave modified files in the working directory for the user to review.

### Branch / worktree naming

Always branch (and create any worktree) off `main` when starting a
task, This is a team project, so the branch name is
`<author>`:

Example: Trọng Minh adding a feature -> `trongminh`

### Commit messages

- Short and to the point, describing the actual task/fix/feature — no filler, no restating the diff.
- **Never** include `Co-Authored-By: Claude`, any other AI attribution, or any signature/trailer of
  any kind. Plain message only.
